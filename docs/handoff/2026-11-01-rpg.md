## 다음 세션 작업: 1단계

### 구현 전에 정한 것 (2026-11-01, design.md에도 기록)

1. **막간 화면 형식**: 선택지는 대사 창 위에 따로 띄운 패널로 보여 준다(페르소나 방식). 휴대폰은 대사 창 바로 위 전체 폭, PC는 1~4 숫자 키로도 고른다. 선택지에 자라는 열매를 미리 쓰지 않고, 고른 뒤 "인내가 자랐어요"처럼 획득 효과로 보여 준다. 열매 단계로 열린 네 번째 선택지에만 그 열매 표시(예: 새싹 모양)를 단다.
2. **에덴의 막간 인물**: 아담과 끝까지 대화한다. 시점은 동물 이름 짓기를 마친 직후, 아담이 잠들기(창 2:21) 전이다. 근거는 창 2:20 "아담에게 꼭 맞는 돕는 이는 없었다". 주제는 이름 지은 기쁨, 혼자라는 마음, 하나님께서 하실 일을 기다림이다. 선택지 예: 함께 기뻐하기(기쁨), 조용히 곁에 있기(화평), 기다려 보자고 말하기(인내). 대화는 사건 흐름을 바꾸지 않는다. 하와와는 열매 모으기 때 짧은 인사만 하고 관계 단계 "만남"을 기록한다.

나머지(경험치·달란트 수치, 칭호 이름 초안, 닮은 인물의 열매 모양, 아담 막간 대사 초안)는 묻지 않고 초안을 만든 뒤 근거와 함께 보여 주고 조정을 요청한다.

### 하위 묶음 (묶음마다 check·build·브라우저 확인·커밋·push)

| 묶음 | 내용 | 표준 문서 |
|---|---|---|
| 1a 저장·수치 | 저장 구조 확장, 예전 저장값 옮기기, 경험치·달란트·열매 수치 데이터 | workflow.md |
| 1b 상태 창·도감 | 레이더 차트(단계로 그림), 닮은 인물, 도감 다섯 분류 3상태 | ui.md |
| 1c 인벤토리 | 도구 탭·꾸미기 탭, 쓰고 나면 사라짐, 기념물은 도감으로 | ui.md, art-3d.md |
| 1d 막간 | 에덴 막간 1개, 선택지와 열매 성장, 관계 단계 | dialogue.md, quests-and-staging.md |

- **1a**: `src/save.js`의 저장 형식에 레벨·경험치·달란트·열매 점수·관계 단계·도감·인벤토리를 더한다. `load`가 예전 저장값을 새 형식으로 옮기고, `scripts/check-data.mjs`가 이를 점검한다. 수치 표는 `src/data/`에 데이터로 둔다(코드에 숫자를 흩지 않는다). 지금 있는 보상 지점(강 찾기, 동물 이름 짓기, 열매 담기, 퀴즈)에 경험치·달란트·열매를 붙인다.
- **1b**: 걷는 중에만 열리는 메뉴(연출 중에는 막음). 화면 작업 전 `hallmark` 스킬을 불러 규칙을 지킨다. 레이더 차트는 `dataviz` 스킬 규칙을 따른다. 동물 도감 카드(`showCard`)는 새 도감과 합친다.
- **1c**: 지금 꾸미기 소품(`LOOK.earth.item`)을 인벤토리 꾸미기 탭으로 옮기는 방식을 정한다. 쉼터 상점은 2단계라 이번에는 보상으로만 얻는다.
- **1d**: 대사 데이터에 막간·선택지·자라는 열매를 데이터로 표현하고 점검한다. 막간 대사는 각색이므로 `ref: null` 또는 근거 주석을 단다.
- `npm run review`(각색 목록 뽑기, design.md "감수")는 1d 끝에 만든다. 에덴 막간이 첫 검수 대상이다.

## 작업 방법과 주의

- 터미널(PowerShell)에서는 실행 정책 때문에 `npm` 대신 `npm.cmd run dev`를 쓴다. 사용자 서버는 localhost:5173, 점검은 127.0.0.1:5174(workflow.md).
- Bash heredoc은 백슬래시(`\n`)를 망가뜨린다. 대사 같은 문자열 수정은 Edit 도구나 Write로 만든 스크립트 파일로 한다.
- 자동화 브라우저는 화면 갱신이 느리다. 움직임은 `__dev.eden.update`로 시간을 앞당기고, CSS 효과는 `getAnimations`로 시점을 정해 캡처한다(workflow.md).
- 확인하지 못한 것: 꾸미기·가죽옷 효과와 탭 전환의 보통 속도 모습, 휴대폰 성능(화면 자르기, 빛 알갱이), 관찰자 비키기의 보통 속도 동작.
