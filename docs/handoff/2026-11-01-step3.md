## 다음 세션 작업: 1-3 가인과 아벨 (창 4장)

### 정한 것

- 퀘스트·도전: 양 치기(아벨의 일, 창 4:2), 제물 준비(창 4:3~4). 막간 인물: 아벨. 핵심 말씀: 창 4:7.
- 가인이 아벨을 치는 장면(창 4:8)은 멀리서 비추고, 다가간 뒤 쓰러지는 모습까지만 보인다. 치는 동작과 피는 보여 주지 않고, 창 4:9~10은 대사로 전한다(quests-and-staging.md, 아직 `[미적용]`).

### 만들 때 순서 (에덴과 같은 틀)

1. `src/data/chapters.js`에 지점(points)을 채우고 `WORLDS`에 나머지 스테이지를 더한다. 지도 표지가 15개가 되면 한 줄에 다 들어가지 않으니 지도 배치(줄바꿈이나 굽이치는 길)를 먼저 고친다. 곁길 두 개는 본 스테이지와 다르게 표시한다(design.md "지도 표시").
2. 대사 데이터 `src/data/cain.js`(장절 형식, 줄바꿈 2판, YHWH 이름표). 막간은 `INTERLUDE` 형식(dialogue.md "막간과 각색 목록")을 그대로 쓴다.
3. 장면 `src/cain.js`: 에덴의 `makeEden` 구조를 본떠 공용 부품(`props.js`)으로 만든다. 들판, 제단 두 개, 양 떼. 무대(`STAGES`)와 비켜 서기, 충돌, 길 안내 규칙을 지킨다.
4. 보상 지점(`REWARDS`), 열매(퀘스트마다 근거 주석), 도감 항목(`src/data/codex.js`: 가인, 아벨, 양, 제단, 놋 땅, 창 4:7 등), 퀴즈.
5. `scripts/review.mjs`의 `STAGES`에 1-3을 더하고 `npm run review`로 `docs/review/cain.md`를 뽑는다.
6. 묶음마다 `npm run check`·`npm run build`, 점검용 서버(127.0.0.1:5174)에서 브라우저 확인, 커밋·push.

## 작업 방법과 주의

- PowerShell에서는 `npm.cmd`를 쓴다. Bash에서 `npx vite --host 127.0.0.1 --port 5174 --strictPort`로 점검용 서버를 띄우고, 끝나면 5174 포트 프로세스를 끈다.
- 한글이 든 파이썬 heredoc은 `python -X utf8`로 실행한다. 그렇지 않으면 문자열 비교가 깨져 수정이 통째로 실패한다. 줄바꿈 기호(`\n`)가 든 대사는 Edit 도구로 고치는 편이 안전하다.
- 자동화 브라우저에서는 머무르기 게이지와 걷기가 실제보다 10배쯤 느리다. 막간은 개발 전용 `__dev.interlude()`로 따로 돌려 볼 수 있다. 스테이지마다 비슷한 점검 함수를 `__dev`에 더한다.
- 코드를 고치면 개발 서버가 페이지를 새로 고쳐서, 브라우저 점검 도중의 상태가 사라진다. 고친 뒤에는 저장값을 다시 넣고 처음부터 돌린다.

## 확인하지 못한 것 (다음 세션에서 같이 본다)

- 창조 일곱째 날 → 쉼터, 에덴 퀴즈 → 쉼터로 돌아오는 흐름(끝까지 플레이해서 보지 않음).
- 동물 이름 짓기 뒤 막간이 이어지는 것과 하와에게 다가가 인사하는 동작(막간은 따로 돌려 확인함).
- 상점 꾸미기(소고, 종려 가지, 수금)와 지팡이가 손에 그려진 3D 모양.
- 조작 안내가 6초쯤 쓴 뒤 사라지는 동작.
