## 다른 PC에서 시작하기

1. `git clone https://github.com/thedaboot/bible-log.git` → `npm install` → `npm run check`·`npm run build`가 통과하는지 본다.
2. 작업 규칙(커밋 규칙, 문서 자리, 이어 만들기, heredoc 주의)은 저장소 루트의 [`CLAUDE.md`](../../CLAUDE.md)에 있고 Claude Code가 자동으로 읽는다. 예전에 한 PC의 메모리에만 있던 내용을 옮겼다.
3. 이 문서 끝의 "마친 뒤 상태"부터 읽는다. 브라우저 점검 시작 코드는 [`../standards/workflow.md`](../standards/workflow.md) "브라우저 확인"에 있다.
4. 도우미 스크립트: `scripts/wrap-lines.py`(대사 줄바꿈), `scripts/add-stage.py`(스테이지 등록).

## 이번 세션의 작업 방식 (사용자 요청, 2026-11-02)

- **스토리를 한 번에 끝까지 만든다.** 스테이지마다 초안을 보여 주고 기다리지 않는다. 대사·막간·수치·도감 메모는 권장안으로 바로 넣고, 감수 목록(`npm run review`)과 아래 "결정 기록"에 근거와 함께 남겨 나중에 한꺼번에 조정받는다.
- 판단이 갈리는 곳(본문에 없는 소품, 장면 순서, 수치)은 권장안을 고르고 `docs/review/decisions.md`에 한 줄씩 적는다: 스테이지, 결정, 근거, 다른 안. 사용자가 이 파일만 보고 조정할 수 있어야 한다.

## 먼저 할 공통 작업

### 1. 키보드로 다 할 수 있게 (사용자 요청)

지금 키보드로 못 하는 곳(2026-11-02 코드 확인):

- 퀴즈 보기: 숫자 키(1~3)로 고르기, ↑·↓로 포커스 옮기기를 더한다. 막간 선택지(1~4 키)와 같은 키캡을 단다.
- 막간 선택지: ↑·↓로 포커스를 옮긴다(지금은 숫자 키와 Tab만 된다).
- 월드 지도: 표지를 고른 상태에서 Enter로 첫 지점에 들어가고, 지점이 여럿이면 ↓로 지점 버튼에 포커스를 옮긴다.
- 메뉴: 탭을 ←·→(또는 Q·E)로 옮긴다. 도감 분류·페이지 넘기기도 키로 된다.
- 도전(새로 만들 것): 이동 WASD, 행동 Space, 도구 F. 화면에 키캡으로 보여 준다.

### 2. 도전 틀 (design.md "도전 조작", 아직 없음)

- 모든 도전이 이동·행동·도구 3가지로 같고, 스테이지마다 행동 버튼의 뜻만 바뀐다. 성공이 가까우면 금빛 신호. 실패해도 감점 없이 다시 하고 결말은 본문 그대로.
- 열매 단계당 보조 8%, 최대 32%(growth.js 수치에 ★로). 어느 열매가 어느 도전을 돕는지 근거를 주석에 적는다.
- 쓸 곳: 1-11 밤새 씨름, 1-12 꿈 풀기. 1-4 방주 짓기(나무 나르기)와 1-9 물동이(물 긷기)도 같은 틀로 만들 수 있으면 쓴다.
- 도구: 물동이(1-9, 창 24:15)는 같은 스테이지 앞부분에서 얻는다. 상점에서 도구를 파는 일도 이때 연다(growth.md).

### 3. RPG 요소 보강 (사용자 요청: RPG적인 요소를 더)

이미 정했지만 코드에 덜 들어간 것부터 채운다. 새 시스템은 만들지 않는다.

- 관계 "동행" 단계: 지금은 만남·대화만 연결됐다(growth.md `[적용됨: 만남만 연결]`). 인물의 일을 함께 하는 퀘스트(예: 1-4 노아와 방주 짓기, 1-9 리브가와 물 긷기)를 마치면 동행에 이르고 열매가 자란다.
- 깊은 대화: 관계 "대화" 이상 + 레벨 조건에서 막간에 열리는 대화(design.md). 여러 스테이지에 나오는 인물(아브라함, 야곱, 요셉)에 먼저 둔다.
- 도감 완성 보상(칭호·꾸미기만), 스테이지 별(볼거리 남음) 동작 확인.
- 레벨로 여는 꾸미기, 상점 품목을 창세기 끝까지의 레벨 속도에 맞춰 다시 본다(growth.md `PLAN`).

## 매 스테이지 점검 목록 (사용자 요청)

- **가독성**: 대사 줄바꿈 2판, 막간 답의 구체성, 화면 안내 해요체, 15px 미만 읽는 글 없음.
- **충돌·겹침**: 인물·동물·소품이 화면에서 겹치지 않는지(화면 가로 방향으로 떼기), 관찰자가 연출 앞을 막지 않는지(무대 `STAGES`), 알림·카드·게이지·선택지·퀘스트 창이 서로 가리지 않는지.
- **시간이 뜨는 곳**: 대사도 조작도 없이 기다리는 구간이 게임 시간 3초를 넘지 않게 한다. 넘으면 걸음을 빠르게 하거나, 카메라를 움직이거나, 대사를 겹친다. 알려진 후보: 1-3 가인이 놋 땅으로 떠나는 걸음(약 7초), 두 형제가 들로 걷는 구간, 스테이지 마침 뒤 2.4초 대기.
- **키보드만으로 끝까지**: 마우스 없이 한 스테이지를 끝낸다.

## 작업 방법과 주의

- PowerShell에서는 `npm.cmd`. 점검용 서버는 Bash에서 `npx vite --host 127.0.0.1 --port 5174 --strictPort`, 끝나면 5174 포트 프로세스를 끈다.
- 편집 스크립트는 Write로 파일을 만든 뒤 `python -X utf8`로 실행한다. Bash heredoc은 `\\n`을 줄바꿈으로 바꾸고 따옴표를 잘못 읽는다. `\n`이 든 대사는 Edit 도구로 고친다.
- 브라우저 점검 요령은 workflow.md "브라우저 확인"(자동화 창 초당 1.5프레임, 45초 스크립트 제한, `window.__run`과 `window.__step`). 스테이지마다 `__dev`에 장면과 막간 점검 함수를 더한다.
- 한 스테이지에만 쓰는 물체는 그 장면 파일에, 두 번째로 쓰이면 `props.js`로 옮긴다(art-3d.md).
- 컨텍스트가 길어지면 자동으로 압축된다. 스테이지를 마칠 때마다 "진행" 표를 고쳐 두면 압축 뒤에도 이어진다.

### A. 도감 완성 칭호

- 지금은 칭호를 주는 계산이 main.js `codexReward` 안에 있어서 `npm run check`로 점검할 수 없다. 계산(월드의 도감을 다 만났는지)을 `src/growth.js`로 옮기고(`codexDone(state, world)` 같은 함수), main.js는 그 함수를 부르게 한다(growth.md "화면 코드는 계산하지 않는다").
- `scripts/check-data.mjs`에 사례를 넣는다: 항목 하나가 빠지면 칭호 없음, 다 채우면 한 번만 받음, 다시 받지 않음.
- 브라우저: 모든 창세기 항목을 채운 저장값으로 아무 스테이지나 마치고, 상태 창 이름 아래에 칭호가 붙는지 캡처한다.

### B. 시간이 뜨는 곳 (대사도 조작도 없이 3초 넘게 기다리는 구간)

- 알려진 후보: 1-3 가인이 놋 땅으로 떠나는 걸음(`src/cain.js` `acts.leave`, 약 7초), 스테이지 마침 뒤 2.4초 대기(main.js의 `setTimeout(r, 2400)` 세 곳), 1-11 에서 일행이 걸어오는 구간, 1-13 형들이 가나안·애굽을 오가는 걸음.
- 고치는 법은 quests-and-staging.md에 있다: 연출을 시작해 두고 대사를 함께 띄우거나(`const walk = …; await g.talk(…); await walk`), 걸음을 빠르게 하거나, 카메라를 움직인다.
- 재는 법: `__dev.speed = 1`로 두고 해당 구간에서 대사 창도 조작도 없는 시간을 `performance.now()`로 잰다. 자동화 창은 걷기가 느리니 게임 시간(속도×거리)으로 계산해도 된다.

### C. 키보드만으로 한 스테이지 끝까지

- 1-9(도구·도전·막간·퀴즈가 다 있다)를 마우스 없이 브라우저 도구의 실제 키 입력(WASD, Space, F, 1~4, ↑·↓, Enter, Esc, M)만으로 처음부터 끝까지 한다. 자동 플레이(`__dev.auto`)는 끄고, 이동이 오래 걸리는 구간만 `__dev.speed`를 올린다.
- 특히 막간 선택지 ↑·↓(코드만 넣고 실제 키로 누르지 않음), 도전 F 키, 메뉴 M·Q·E를 본다. 막히는 곳은 고치고 ui.md "키보드"에 적는다.

### D. 휴대폰 폭

- 320·375px(workflow.md "휴대폰 폭은 iframe")에서 도전 패널, 퀴즈 키캡, 도감 키 안내, 막간 선택지가 가로 스크롤 없이 들어가는지 본다. PC를 먼저 다듬는 방침(design.md)이라 깨지지 않는 정도만 맞춘다. 키캡은 휴대폰에서 이미 숨는다(`.choice__key`).

### E. 도전 난이도

- `CHALLENGE`(src/data/growth.js, ★: 구간 20%, 속도 0.75)를 직접 쳐 보고 정한다. 기준: 열매가 씨앗일 때 성공률 절반 안팎, 실패해도 감점이 없으니 너무 쉽지 않게. 1-4 방주, 1-9 낙타, 1-11 씨름, 1-12 꿈 풀기 넷을 같은 수치로 한다.
- 바꾼 값과 이유를 growth.md와 decisions.md에 적는다.

### F. 창세기 전체 수치 다시 보기 (design.md "만들면서 체험하고 합칠 스테이지를 정한다")

- 할 일: `PLAN`(스테이지 120, 스테이지당 150)과 비교해 레벨 곡선(`xpToNext`)과 칭호 레벨이 맞는지 보고, `npm run check`의 속도 점검이 실측과 맞게 가정을 고친다. 상점 값(소고·종려 가지·수금)을 창세기 끝 달란트에 맞춘 권장안을 decisions.md에 올린다. 합칠 스테이지 후보가 있으면 근거와 함께 제안만 한다(직접 합치지 않는다).
