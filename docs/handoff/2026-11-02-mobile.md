## 다음 세션 작업: 사용자 스크린샷 29장 반영

사용자가 휴대폰 화면 캡처 약 29장과 장마다 요청을 준다. 모바일이 중심이고, 같은 문제가 데스크톱에도 있는지 함께 본다.

### 진행 방법

1. 받은 캡처를 장마다 번호(S01~S29)를 붙여 아래 표에 한 줄씩 적는다: 화면, 요청, 원인(코드 자리), 고칠 방법. 비슷한 요청은 묶는다.
2. 화면을 바꾸기 전에 `hallmark` 스킬로 기존 토큰·부품을 재사용하는지 점검한다(CLAUDE.md 규칙). 새 값은 tokens.css에 토큰으로 올린다.
3. 묶음마다 고치고 `npm run check`·`npm run build`를 돌린다.
4. 브라우저 확인: 점검용 서버(5174)를 띄우고 `http://127.0.0.1:5174/dev/mobile.html?w=390&h=844`에서 캡처의 화면을 재현해 고친 뒤를 캡처한다. 같은 화면을 `?w=1280&h=720`(PC)과 `?w=740&h=360`(가로)에서도 본다. 도우미 사용법은 [dev/mobile.html](../../dev/mobile.html) 머리 주석에 있다.
   - 틀 하나만 띄운다. 셋을 한꺼번에 띄우면 자동화 창이 멈춘다.
   - 브라우저 도구의 스크립트 실행은 45초에 끊긴다. `finish()`는 40초까지만 돈다.
   - 저장 없는 첫 방문은 `?fresh=1`로 본다.
5. 묶음마다 커밋·push(배포)하고 표의 상태 칸을 채운다. 판단이 갈린 곳은 decisions.md에 한 줄씩 남긴다.
6. 끝나면 사용자에게 장 번호별로 고친 것과 확인 수준(실측/확인 가능/미확인)을 보고하고, 실제 기기에서 다시 볼 장을 짚어 준다.

### 이 세션에서 끝낸 뒤 남은 것 (2026-11-02 다섯째 세션)

- 실제 휴대폰에서 다시 볼 것: S02(키보드가 올라올 때 바탕), S04(조이스틱 손맛), S09(두 번 탭 확대 막힘), S20(도전 판정 여유 0.15초가 맞는지), S22(세로 화면에서 방주가 화면 폭보다 길어 벽처럼 보이는지), S24(지어낸 글자가 기기 글꼴에서 깨지지 않는지).
- 감수: decisions.md "대사", "대사 2차" 줄의 본문 각색(창 15:2, 32:9, 3:20, 42:9, 18:11~12, 18:23~32, 유 1:15, 10:32).
- 노아 대사 전체 다듬기는 연출 작업 때 일부만 했다(막간, 새로 넣은 본문). 다른 스테이지처럼 dialogue.md "대사 다듬기" 기준으로 한 번 더.
- 에녹 장면 곳곳에 정체를 모르는 어두운 가시 모양 물체가 하나 보인다(미확인).
- 도감 후보: 도마뱀, 물고기(1-4). 도감 칸 그림은 지금 분류 그림이고, 항목마다 그림은 뒤로 미뤘다(ui.md).
- 엎드림 동작은 1-7 안에만 있다. 창 24:26, 33:3, 42:6에도 쓰려면 field.js로 옮긴다.
- 점검 도구: `dev/cdp.mjs`와 `dev/steps/`(workflow.md "브라우저 확인"). 점검 서버에 HMR이 켜져 있으면 여러 작업이 동시에 파일을 고칠 때 자동 플레이가 끊긴다.

### 주의

- 사용자는 말하지 않은 곳까지 전반을 봐 주길 원한다. 캡처 한 장을 고칠 때 같은 부품을 쓰는 다른 화면(PC·가로 포함)도 함께 고친다.
- 판단으로 위치를 바꾸기 전에 일반적인 앱 관례를 따른다(이름 입력을 위쪽으로 옮겼다가 되돌린 일이 있다).
- 커밋 메시지에 Co-Authored-By 줄을 넣지 않는다.
