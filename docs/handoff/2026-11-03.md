## 다음 세션 할 일

### 1. 사용자 피드백 2차

사용자가 캡처와 글로 새 피드백을 준다. 앞 세션과 같은 방법으로 한다.

1. 받은 것마다 번호(F01부터)를 붙여 아래 "요청 표"에 한 줄씩 적는다: 화면, 요청, 원인(코드 자리), 고칠 방법.
2. 화면을 바꾸기 전에 `hallmark` 스킬로 토큰·부품 재사용을 점검한다(CLAUDE.md).
3. 묶음마다 고친다. `npm run check`·`npm run build`를 돌리고, 고치기 전과 후를 캡처로 비교한다(아래 "점검 도구").
4. 묶음마다 커밋하고 push한 뒤(자동 배포), 표의 상태·커밋 칸을 채운다. 판단이 갈리면 일반 모바일 앱·게임 관례를 따르는 권장안으로 하고 decisions.md에 한 줄 남긴다.
5. 같은 부품을 쓰는 다른 화면과 PC(1280×720)·가로(740×360)도 함께 본다.
6. 사용자가 고를 일은 `AskUserQuestion`으로 묻는다(사용자가 말한 /grill-me). 선택지에는 권장안을 맨 앞에 둔다.

## 점검 도구와 주의 (앞 세션에서 배운 것)

- **헤드리스 캡처:** `node dev/cdp.mjs <w> <h> dev/steps/<스크립트>.mjs [저장 폴더]`. 휴대폰 폭은 터치 기기로 흉내 낸다. 예시 스크립트는 `dev/steps/`에 있다(prologue, choice, eden, map, look, codex, challenge, cain-trial, mamre, noah-ark). 저장값 도우미는 `_save.mjs`(`boot`, `SAVE`, `next`)다. 캡처는 `dev/shots/`에 쌓이고 커밋하지 않는다. 자세한 것은 [workflow.md](../standards/workflow.md) "브라우저 확인".
- **고치기 전과 비교:** 다음 순서로 한다.
  1. `git worktree add -f ../bible-before HEAD`
  2. `cmd //c "mklink /J ..\bible-before\node_modules node_modules"`
  3. 5175 포트에 서버를 띄우고 같은 스크립트를 `BASE=http://127.0.0.1:5175/`로 돌린다.
  - 지울 때는 먼저 `cmd //c "rmdir ..\bible-before\node_modules"`로 연결만 끊는다. 그냥 지우면 본 node_modules까지 지워질 수 있다. 그 뒤 `git worktree remove --force ../bible-before`와 `git worktree prune`을 한다.
- **여러 작업을 나란히 돌릴 때(에이전트)**
  - 스테이지마다 파일을 나눠 맡긴다(stages/<id>.js, data/<id>.js). 공용 파일(main.js, field.js, props.js, ui.js, style.css)은 한 작업만 고친다.
  - 에이전트는 커밋하지 않고, decisions.md에 넣을 줄을 보고로만 낸다. 커밋은 메인이 묶어서 한다.
  - 5174 서버는 HMR(파일이 바뀌면 새로 고침)이 켜져 있어서, 다른 작업이 파일을 저장할 때마다 자동 플레이가 끊긴다. 에이전트마다 HMR을 끈 서버를 다른 포트에 띄우게 한다(`npx vite --host 127.0.0.1 --port <포트> --strictPort`와 vite `server.hmr: false` 설정은 작업 폴더 밖에 둔다).
  - `npm run review`는 감수 목록 전부를 다시 쓴다. 나란히 작업할 때는 마지막에 메인이 한 번만 돌린다.
- **편집:** heredoc은 백슬래시를 망가뜨린다. 여러 줄 편집은 Write로 .py를 만들어 `python -X utf8`로 돌린다. 정규식이 든 점검 스크립트는 Write로 만들고 `String.raw`를 쓴다.
- **커밋 메시지:** Co-Authored-By 줄을 넣지 않는다(CLAUDE.md).
- **끝나면:** 점검 서버(5174, 5175, 그 밖에 띄운 포트)를 끈다.
