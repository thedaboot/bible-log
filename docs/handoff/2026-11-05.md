## 다음 세션 할 일

### 1. 사용자 피드백 4차

사용자가 캡처나 글로 새 피드백을 주면 앞 세션과 같은 방법으로 한다.

1. 받은 것마다 번호(F41부터)를 붙여 아래 "요청 표"에 적는다: 화면, 요청, 원인(코드 자리), 고칠 방법.
2. 화면을 바꾸기 전에 `hallmark` 스킬로 토큰·부품 재사용을 점검한다(CLAUDE.md).
3. 묶음마다 고치고 `npm run check`·`npm run build`, 고치기 전과 후를 캡처로 비교한다.
4. 묶음마다 커밋·push(자동 배포), 표의 상태·커밋 칸을 채운다. 판단이 갈리면 모바일 앱·게임 관례를 따르는 권장안으로 하고 decisions.md에 한 줄. 사용자가 고를 일은 `AskUserQuestion`으로 묻는다(권장안을 맨 앞에).
5. 같은 부품을 쓰는 다른 화면, PC(1280×720)·가로(740×360)도 함께 본다. "말한 곳만 고치지 말고 비슷한 문제도 찾아 고친다"가 사용자 요청이다.
6. 보고할 때 "하지 않은 것"은 이유(할 수 있는데 안 함 / 할 수 없음 / 필요 없음)를 함께 적는다. 앞 세션에서 사용자가 이 구분을 물었다. 할 수 있는 일은 미루지 않고 한다.

## 점검 도구와 주의 (앞 세션에서 배운 것)

- **서버:** 사용자 서버는 `npm run dev`(localhost:5173). 점검은 HMR을 끈 서버로 한다. 설정 파일은 저장소 밖에 둔다(예: `export default { base: './', server: { hmr: false } };`를 임시 폴더의 `vite-nohmr.config.mjs`로 저장하고 `npx vite --config <그 파일> --host 127.0.0.1 --port 5174 --strictPort`). HMR이 켜져 있으면 다른 작업이 파일을 저장할 때마다 자동 플레이가 끊긴다. 끝나면 띄운 포트를 모두 끈다.
- **캡처:** `node dev/cdp.mjs <w> <h> dev/steps/<스크립트>.mjs [저장 폴더]`. 저장값 도우미 `dev/steps/_save.mjs`(`boot`, `SAVE`). 캡처는 `dev/shots/`(커밋하지 않음). 여러 장은 PIL로 한 장에 이어 붙여 보면 컨텍스트를 아낀다.
- **스테이지 전반 점검 스크립트(dev/steps/)**
  - `r3-keys.mjs`: 첫 화면·쉼터·메뉴·상점·지도·1-9를 키 입력만으로(22항목)
  - `r3-stages.mjs`: `STAGES=creation-1,eden,...` 키 입력만으로 스테이지를 끝까지. 꾹 누르기(hold)는 Space를 누른 채 구간에서 뗀다. 걷는 거리만 `__dev.goNext`로 건너뛴다. 저장값의 '완료' 기록을 지우고 시작한다(안 지우면 거짓 통과)
  - `stuck-scan.mjs`: `STAGES=...` 자동 플레이로 돌며 걷다 막혀 순간 이동한 기록(`globalThis.__stuck`)을 모은다
  - `f23-pos.mjs`: `STAGE`, `STOP` 대사에서 멈춰 막간 화면을 찍는다
  - `inv3.mjs`, `shop.mjs`, `menu-land.mjs`, `f2-ui.mjs`: 인벤토리·상점·메뉴 화면
- **CDP 키 입력:** Enter는 `text: '\r'`(String.fromCharCode(13))를 실어야 버튼이 눌린다. 템플릿 문자열 안에 정규식 백슬래시를 넣으면 사라진다(정규식 대신 split으로 숫자를 읽는다).
- **느린 헤드리스 창:** 대사 없는 연출(창조, 홍수)이 1분 넘게 화면이 그대로일 수 있다. 멈춤 판정을 넉넉히 둔다. 짧은 연출 중간은 performance.now를 느리게 해서 찍는다. 같은 서버에 크롬을 셋 이상 동시에 띄우면 첫 화면이 늦게 떠 boot가 실패한다.
- **커밋 확인:** 다른 작업이 아직 고치는 파일을 빼고 커밋할 때는, 커밋한 판만 따로 꺼내 점검한다: `git worktree add -f ../bible-verify HEAD` → `cmd //c "mklink /J ..\bible-verify\node_modules node_modules"` → 그 폴더에서 `npm run check`·`npm run build` → `cmd //c "rmdir ..\bible-verify\node_modules"`(연결만 끊기, 그냥 지우면 본 node_modules가 지워질 수 있다) → `git worktree remove --force ../bible-verify` → `git worktree prune`.
- **에이전트 나란히 쓰기:** 스테이지 파일(stages/<id>.js, data/<id>.js)이나 props.js처럼 파일을 나눠 맡기고, 공용 파일(main.js, field.js, ui.js, style.css, menu.js)은 메인이 고친다. 에이전트마다 HMR 끈 서버를 다른 포트(5181~5185)에 띄우게 하고, 커밋은 메인이 한다. 에이전트가 공용 코드에 우회(MutationObserver, 화면 값 읽기)를 넣었으면 공용 옵션으로 바꿔 우회를 지운다.
- **편집:** Bash heredoc은 백슬래시를 망가뜨린다. 여러 줄 편집은 Write로 .py를 만들어 `python -X utf8`로 돌린다. 임포트 목록 끝에 덧붙일 때 쉼표가 두 번 붙지 않게 본다(앞 세션에서 빌드가 한 번 깨짐).
- **커밋 메시지:** Co-Authored-By 줄을 넣지 않는다(CLAUDE.md).
