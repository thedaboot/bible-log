# 2026-11-14 인수인계: 전면 개편 진행 중

실측: `feat/cinematic-redesign`에서 게임 전면 개편을 진행한다. 네 UI 묶음과 공용 멈춤·문구/도구 사용을 검증했다. UI 커밋0729d43을 기능 브랜치에 push했고 main에 배포하지 않았다. 다음은 실제3D와 피드백39개 장면이다. 게임 전체는 미완료다. 추적되지 않은 AGENTS.md는 사용자 파일이므로 임의로 추가하지 않는다.

## 결정과 범위

- 사용자는 Fable 5.2 본격 구현을 승인했다. 같은 방향 승인을 다시 묻지 않는다. 청소년·성인 대상의 따뜻하고 성숙한 입체 세계(A)를 기본으로, 중요한 밤에는 C의 조명, 지도·기록장에는 B의 삽화 감각을 제한해서 쓴다. 에셋도 같은 기준을 따른다.
- 새 UI를 먼저 전면 설계했고 사용자는 분위기를 긍정적으로 평가하며 PC·모바일의 위치·정렬·실제 표현 보완을 요청했다. 그 조건을 검증한 뒤 제품 동결을 해제했다. 기존 시각 디자인을 새 기준으로 쓰지 않는다.
- 기존 스토리·성경 맥락·사실·장절과 저장 호환을 유지한다. [게임 설계](../design.md), [제작 표준](../standards/README.md), [사용자 피드백39개와 완료 기준](../review/feedback-2026-11-13.md)이 게임의 원본 문서다.

## 현재 구현

1. 첫 묶음: 새 tokens.css, app.css·scene.css, 탐험 HUD, 대사·선택지·퀴즈, 멈춤·완료를 실제 게임에 연결했다. `src/ui.js`·`main.js`·`index.html`의 기존 호출 계약과 저장·쪽 나누기·선택지 번호를 유지했다.
2. 넷째 묶음에서 전체 화면의 스타일 이행을 마치고 `style.css`·옛 그림 두 파일·두 점검 화면과 legacy/reset/임시 토큰을 제거했다. `base.css`가 숨김·캔버스·폰트·폼·전환의 기반을 맡고 새 선 그림을 공용으로 쓴다. 실제3D 외형은 다음 묶음이다.
3. 둘째 묶음은 기록장의 네 갈래·여정 지도·상점·모습/이름 입력이다. 실제 인물 팩토리의3D 미리보기, 성장 나무, 새 선 아이콘을 연결했고 지도 기원 복귀·SVG 표시·상점 높이·미리보기 잘림을 고쳤다. 실제 플레이는 Three.js 장면으로 유지하며 콘셉트 이미지를 완성된3D로 대신하지 않는다.
4. 셋째 묶음은 도전8종·알림·머무르기·도감 카드·조작/다음 단추다. 멈춤/기록장 동안 도전과 실제 월드 이동·공용 연출 시간을 정지하고 복귀할 때 시간을 건너뛰지 않게 고쳤다. 넷째에서 조이스틱/화살표를 새로 입혔고 길 안내가 모바일 안전 영역을 침범하던 계산도 수정했다.
5. 다섯째에서 승인된 데이터 문구29곳과 머무는 안내4곳을 고쳤다. 필요한 물동이는 옛 도구함이 가득 차도 중복 없이 받고, 내려놓거나 다른 소품으로 바꿔도 긷기/붓기 전에 다시 든다. 구유 셋 뒤 소모하고, 쓰지 않는 옛 도구 기록은 보존하며 "보관"으로 보인다. 소지품에 실제 사용처/사용법을 적고 빈 도구 자리 노출을 없앴다.

## 이어갈 순서

- 실측: 다섯째는 check/build/review와 승인안29곳의 정확 대조를 통과했다. 다른 데이터/id/장절/선택지/보상은 보존했다. 실제390 기본 저장·1280 가득 찬 옛 도구 저장에서 획득/내려놓기/다른 소품/붓기/소모와 받기 전·중간·사용 후 이어하기를 통과했다.320·740의 실제 기록장/상점과740의 F 도구 계약도 통과했다. 실제3D의 접촉/자세와 최종 구도는 다음 단계다.

- 실측: 넷째는 최종 check/build와 UI 구조/숨김/실제 조작을320~2560폭에서 해당 화면별로 통과했다. 실제 구매/기록장320·1280, 이름390, 도전8종/키보드1280, 나가기 저장/지도/움직임 줄이기740을 확인했다.390·844의 안전 영역과320의 실제 조이스틱 이동/취소·길 안내도 통과했다.2560 캡처는 기존 CDP 드라이버의 전송 실패로 설치된 Playwright를 통해 같은 검증을 통과했으며 정확한 드라이버 실패 원인은 미확인이다.

- 로컬 .orchestrator가 있으면 최신 조정 체크포인트와 state.yaml, 진행 중인 워커를 먼저 확인한다. 기존 main과 같은 Fable 세션을 재사용한다. 워커는 파일을 수정하고 검증 실행은 조정 세션이 맡고 있다. 실행 중인 파일을 겹쳐 고치지 않는다.
- 로컬 운영 기록이 없어도 위 게임 설계·표준·피드백으로 이어간다. 전체 UI를 실제 기능에 연결한 뒤 공용3D·스테이지를 끝까지 만들고, check/build·실제 입력·저장 호환·전체 스테이지를 검증한다. 내용 기준선을 다시 캡처해 변경을 숨기지 않는다.
- 사용자의 5173 서버는 건드리지 않는다. 브라우저 검증은 별도5174에서 한다. 문구는 검토한 범위만 바꿨고 저장 구조는 유지했다. 배포·커밋 규칙은 프로젝트 지침을 따른다.

미확인: 실제 iOS/PWA·낭독기, 최종3D의 밝은 배경 가독성과 배우 가림, 사람의 손맛·난도다. 워커와 main의 동일 세션 재연결은 이번에 확인했지만 캐시·중간 호출·모든 서버가 재시작을 그대로 견딘다고 보장하지 않는다.
