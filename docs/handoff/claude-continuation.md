## 모델·도구·역할

- Claude Code에서 선택한 **Claude 모델 하나**를 기본으로 쓴다. 이전 작업은 계정에서 Fable5.2로 실행했다. 모델 이름을 추정하거나 다른 벤더로 대체하지 않는다. 새 다중 에이전트 구조나 모델 라우터를 만들지 않는다.
- 직접 코드를 읽고 편집하며 허용된 터미널로 Node/npm/Git/Chrome 검증을 실행한다. 이들은 실행 도구이고 다른 AI 모델 호출이 아니다. Codex CLI·Codex 워커·외부 이미지 모델·추가 유료 API/키를 사용하지 않는다. 기존 생성 에셋은 그대로 쓸 수 있다.
- 옛 인계의 "root가 실행", "워커는 Bash 금지", "root QA파일 미수정"은 당시 세션의 역할/승인 상태를 기록한 것이다. 이번 사용자 인계에 따라 **제품 구현과 아래 검증 도구의 유지·실행을 Claude가 함께 맡는다.** 코드 수정 허용 범위는 `src/`, `public/`, `index.html`, `docs/`, `scripts/`, `dev/`, 필요한 프로젝트 패키지 파일이다. 사용자 `AGENTS.md`는 임의 수정·추가하지 않는다.
- 도구 승인이 필요하면 Claude의 정상 승인 절차를 사용한다. 권한 제한·ACL·전역 설정·승인 화면을 우회하지 않는다. 허용되지 않은 명령을 실행했다고 보고하지 않는다.
- 기존 Codex main은 대기 상태로 남는다. 재개하거나 새 main을 만들 필요가 없다. `.orchestrator/state.yaml`·wiki·배정·잠금은 계속 읽기만 한다. 제품 진행과 검증은 저장소 문서에 기록하면 되므로 운영 위키 갱신을 기다리지 않는다. 역할 환경 변수를 main으로 위장하거나 잠금을 지우지 않는다.
- 기존 Claude 세션을 쓸 경우 입력칸에 남은 오래된 "계속"/"중단" 초안을 먼저 확인한다. 새 사용자 재개 프롬프트가 최신 기준이다. 다른 세션과 같은 파일을 동시에 편집하지 않는다. 이 문서 준비 과정에서는 Worker를 재시작하지 않았다.

## 첫 작업: PC의 조건별 구도

**실측:** 마지막 check/build는 통과했다. 같은 실제WASD 우물 진입에서390×844는 배우 전체/대사 그늘 제외/천사 겹침0을 통과했다. 이전1280×720은 관찰자 y-35~278, 종-47~136, 리브가-91~107, 천사-29~242로 머리가 위로 잘렸다. 이후 인계한 도구로 실행한1280 한 차례는 관찰자 y248~470, 천사/관찰자 겹침0으로 통과했다. 카메라 소스는 Git blob `aa43a1e0420cdf1f7ce5aaa42ad170abbc71d5f6`으로 같고 제품 수정은 없었다. `assets/well-pc-known-failure.*`와 `well-pc-repeat-pass.*`를 함께 본다. 후속JSON에는 카메라/배우 세계좌표도 있다. 한 차례 통과를 해결 완료로 처리하지 않는다.

- `src/main.js`: `applyView`, `frameFit`, tick의 `camTarget/camLook/camDist/zoom`과 UI 제외 영역부터 본다. `src/stages/rebekah.js`의 `g.cam(WELL,12)`와 `g.stage('well')`, 관찰자를 비키는 위치도 함께 확인한다.
- 접근 방향·관찰자가 비키는 자리·카메라 수렴 시점에 따라 결과가 달라질 가능성은 있으나 원인은 **미확인**이다. 앞선 실패의 nearby 배열은 비어 있고 후속 통과에는 종/리브가가 들어 있다. 원근 투영·초점 이동·깊이·배율과 함께 확인한다. 추정만으로 오프셋을 더하거나 사람을 숨기지 않는다.
- 실제 메시 꼭짓점 투영과 DOM의 대사/강한 그늘 영역을 검사한다. 월드AABB의 가상 꼭짓점은 올린 물동이 잘림을 과장해 과거 검증기를 고친 적이 있다. 다시 그 판정으로 되돌리지 않는다.
- 1280/390 같은 사건에서 전체 배우·상호 가림·말하는 사람 전환 때의 안정성을 함께 만족시킨다. 필요한 배우가 화면에 들어와도 천사가 관찰자를 가리거나 대사 그늘 뒤에 서면 실패다.

## 지킬 기준

- **일관성:** 청소년·성인 대상, 따뜻하고 성숙한 입체 세계(A), 절제된 영화 연출이다. C는 중요한 밤 조명, B는 지도/기록장 삽화에만 제한한다. 렌즈 비교의 "시안B"는 아트 방향B로 바꾸는 뜻이 아니다. 새 tokens/공용 부품을 기준으로 맞추고 개편 전 픽셀·원색·장난감 스타일을 다시 참고하지 않는다.
- **내용/저장:** 성경 사건 순서·장절·인물·선택지 의미/순서·열매·보상/unlock id를 보존한다. `resume.n`은 대사/퀘스트/도전 묶음의 호출 순번이므로 불필요하게 묶음을 쪼개거나 순서를 바꾸지 않는다. 지형이 바뀌면 옛 저장 위치의 안전한 같은 구역 복구를 검증한다.
- **충돌한 옛 결정:** 모리아에서 행동 직전 제지/숫양을 잡아 옮기는 연결은 최신 사용자 F69/70이 과거 "서술만/빛 속 축소" 결정보다 우선한다. 본문 결과를 바꾸지 않고 피·상처를 자세히 그리지 않는다. 판단은 `docs/review/decisions.md`에 근거와 함께 남긴다.
- **요셉 울음:** 창42:24 돌아서 울기,43:30 방에서 울기,45장 정체 공개 뒤 형제들과 울기는 다르다. 모든 울음을 뒤돌리기로 일괄 치환하지 않는다.
- **조작/가독성:** 키보드만으로 전체 조작, 안내15px 이상·해요체·대사 줄바꿈2판, 긴 이름/문구·안전 영역·스크롤·멈춤·빠른 재입력·지도X의 원래 화면 복귀를 지킨다. 기다림만3초를 넘기는 구간을 만들지 않는다.
- **검증/저장:** 수정한 장면부터 check/build·실제 끝까지 플레이하고 공용 변경은 관련 장면으로 넓힌다. 전부 끝났다는 보고는39개 각각의 구현·실제 증거와 전체 여정/저장 검증 뒤에 한다. 완료하지 않은 PC/모바일·iOS/PWA·폰FPS·사람의 손맛은 미확인으로 남긴다. 적절한 단위로 기능 브랜치에 커밋/push하고 main 배포는 별도 요청 전까지 하지 않는다.

## 권장 스킬

- `hallmark`: 새 UI 토큰·부품의 재사용과 시각 일관성을 검토한다.
- `investigate-first` 또는 원인 진단 스킬: PC 구도/동선/간헐 입력 실패를 재현한 뒤 고친다.
- 한국어 문법/문체 스킬: 사실·인물 말투를 유지하면서 어색한 대사·안내만 정돈한다.

Claude에서 사용할 수 있는 스킬만 적용하고 다른 모델 호출을 포함한 스킬/플러그인은 쓰지 않는다. 스킬 설치가 필요한 경우 기존 프로젝트 표준의 해당 검토를 직접 수행할 수 있으며, 새 모델·새 운영 시스템을 도입하는 이유로 삼지 않는다.
